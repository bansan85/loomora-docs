# ADR 0004: A fallback applies to the problematic case only

- **Status**: accepted
- **Date**: 2026-11-13
- **Spike / requirement**: S1 / FR-021, FR-022 (rule "Fallbacks" of CLAUDE.md)

## Context

The rule: never apply the most restrictive fallback to everyone. A fallback is applied only to the problematic case (a platform, compiler, OS version or architecture) and the modern version is used everywhere else. The mechanism is chosen per case: a compile-time switch for a target-wide limit (toolchain flag, feature macro), a run-time check (`GetProcAddress`, version query) when one binary must serve old and new systems. Every fallback is declared in `validation/fallbacks.json` with the platforms that take it.

The code written for spike S1 was built for Windows 2000, the hardest target, and several of its choices were applied to every target. This ADR audits the code and the build files for such choices, changes the ones whose benefit could be verified, and keeps the others with the reason.

## Decision

- Switches of the Windows 2000 case live in `cmake/toolchains/mingw-w64-win2000-i686.cmake` (`LOOMORA_TARGET_WIN2000`, `LOOMORA_AVOID_IOSTREAM`, `_WIN32_WINNT=0x0500`); the x86_64 toolchain keeps `LOOMORA_AVOID_IOSTREAM` (XP x64 floor) and sets `_WIN32_WINNT=0x0502`.
- New or re-scoped fallbacks in `validation/fallbacks.json`: `win2000-getthreadid-shim`, `selftest-no-iostream`, `message-font`, `visual-styles`, `static-cxx-runtime-linux`; `platform_ids` of the six existing entries filled from the probe records of the trials (`dark-mode` and `dpi-awareness` taken by `windows-2000-x86`, `cxx17-nodiscard` by all three platforms, the others by none).
- Windows 11 is listed under `selftest-no-iostream` only because its deliverable is the x86_64 build of a toolchain whose floor is XP x64; Windows 11 itself would run `<iostream>`. XP x64 has no platform record.

## Not verified

- The manifest entries and the message font on Windows XP, Vista, 7, 8, 8.1, 10; DPI above 100%; a Windows 2000 with a service pack; real hardware; Windows XP x64 (the 0x0502 level, the x86_64 selftest without `<iostream>` and every entry of the x64 allowlist marked `verify` remain unconfirmed there).
- The GTK UI on any GTK older than 3.24.41 and on a distribution without libstdc++.
- The vector runs of the three trials were repeated with the new builds (the re-runs are not stored, their results are in the verdicts; the new captures and measurements are in `validation/evidence/adr-0004/`); the earlier evidence was produced with the earlier executables and stays in place (see the verdicts).

## Consequences

- A fallback is added together with: the switch in the toolchain file or a run-time check, its entry in `validation/fallbacks.json` with `platform_ids`, and a measurement on the platform it concerns. A change that cannot be measured on its target is written as a proposal here, not made.
- The MinGW linker stamps the build time in the PE header, so each build of the Windows executables has another hash; verdicts name the hash that was run.
